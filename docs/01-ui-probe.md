# 第一步：创建测试界面

目标：显示状态文本和“测试连接”按钮，挂载 Lua 后区分“客户端加载”“等待服务器”“服务器已回应”。本步骤不涉及奖励、买入或扑克规则。

## 1. 保留当前人数配置

用户截图已显示：自定义人数 1～8、包含所有人、必要分组开启。开发阶段先保留，正式匹配策略后续另设；发牌逻辑仍至少需要两名有效入座者。

## 2. 打开客户端画布

1. 关闭当前关卡设置窗口，按 ESC 打开系统菜单。
2. 进入“界面控件组管理”，打开“界面布局”。
3. 使用“添加界面控件”入口添加“客户端控件容器”。部分入口文案可能显示为添加界面控件模板，以实际界面为准。
4. 外层容器命名为 `PokerClientContainer`，确保它被放在当前生效的界面布局中，处于开启和可见状态。
5. 选中它，在“画布设置”中点击“前往编辑”。
6. 此时进入客户端控件画布。外层的“客户端控件容器”本身属于服务器控件；Lua 要挂到里面的客户端控件上。

如果在界面布局找不到该类型，先记录当前页面，不要用普通文本框或交互按钮替代。

## 3. 建立三个控件

画布中若已提供默认的客户端容器节点，把它命名为 `PokerRoot`。若没有，则添加“容器节点”并命名。脚本必须挂载到这个节点。

在 `PokerRoot` 下建立两个直接子控件：

| 类型 | 控件名 | 初始显示 |
| --- | --- | --- |
| 文本框 | `StatusText` | `原神赌场：德州扑克 · 等待脚本加载` |
| 预设按钮 | `TestButton` | `测试连接` |

名称大小写保持一致。`StatusText` 和 `TestButton` 必须是 `PokerRoot` 的直接子节点，不要再放进别的面板。它们不能是外层的服务器控件。

状态文本建议宽约 600、高约 100，按钮宽约 260、高约 70，先摆在屏幕中间且互不遮挡；这些是调试布局建议，不是最终美术尺寸。先保持画布默认分辨率。

如果预设按钮没有默认文字外观：在 `TestButton` 下增加客户端文本框 `ButtonLabel`，写“测试连接”，给它一个可辨认的背景色；在预设按钮的默认、悬停、按下、不可用四种状态节点中都引用这个 `ButtonLabel`。官方允许不同状态引用同一个子控件。后面再区分配色。

开启预设按钮的“可被光标射线检测”和“按钮是否可用”。在 `PokerRoot` 中开启常驻光标（脚本也会设置 `showCursor`）。如有初始激活或显示配置，保持开启。

**当前操作检查点：创建好外层容器并进入客户端画布后，查看控件树和右侧详情，确认类型和层级，再继续映射脚本。**

## 4. 映射脚本

这一步在前三步完成后执行。

1. 将仓库中的 `client/dev/ConnectionProbe.lua` 保存在本机固定路径。可放在本地 Git 项目中，避免使用临时下载路径。
2. 打开千星沙箱的“客户端脚本资源管理器”。
3. 在客户端脚本文件夹内右键，选择“新建脚本映射”，关联该 `.lua` 文件。
4. 回到客户端画布，选择 `PokerRoot`，在“脚本”页签中添加这个映射。
5. 确认仅挂载一次。保存关卡，再开始试玩。

不要挂到外层 `PokerClientContainer`，也不要同时挂到 `StatusText` 和 `TestButton`。仅下载文件、没有映射或挂载，不会让脚本运行。

## 5. 判读结果

| 看到的状态 | 可以说明什么 |
| --- | --- |
| 仍是“等待脚本加载” | 尚未确认脚本启动；检查映射、挂载和激活状态 |
| “客户端脚本已加载” | 根节点、子控件和脚本初始化已成功 |
| 点击后“等待服务器” | 点击监听已执行并尝试发送；不能据此宣布服务器成功 |
| 五秒后超时 | 没有收到匹配回包；未接服务器时属于预期结果 |
| “服务器已回应第 N 次请求” | 收到当前控件和请求编号对应的服务器信号 |

发送过程中按钮暂时不可用，防止重复点击；超时或回应后恢复。发送异常也会恢复按钮，并输出错误日志。

出现报错时在千星日志中勾选“客户端脚本”查看。先将可见状态和错误截图发回，再按真实情况调整。

## 6. 后续服务器验证

信号名、参数顺序和待配置节点见 [02-signal-contract.md](02-signal-contract.md)。当前代码文件不是服务器节点图，不会自动创建监听与回包节点。

双人测试要求 A 的请求只回给 A，B 的请求只回给 B；客户端自身过滤请求号不能代替服务器正确选择目标玩家。
